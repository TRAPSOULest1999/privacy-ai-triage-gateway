THE DESIGN

Privacy comes
before the prompt.

A deliberate boundary between
customer information and classification.

01PROTECT

Remove sensitive identifiers.

Pattern matching handles supported IDs, emails, phones, cards, and account references. Local Presidio can add contextual detection.

02UNDERSTAND

Keep the operational context.

Sanitized text retrieves relevant runbooks. Local Ollama classifies the issue, with deterministic rules as a fallback.

03DECIDE

Leave room for judgment.

Security incidents and decisions below the configured confidence threshold are recommended for human review.

THE PROBLEM

Support automation needs the issue's context, while customer identifiers introduce unnecessary exposure.

THE IMPLEMENTATION

ASP.NET Core orchestrates redaction, in-memory keyword runbook retrieval, local inference, and a human-review policy. The interface makes the returned decision inspectable.

C# / .NET 8Presidio integrationOllama integrationxUnit
THE EVIDENCE

Five synthetic golden tickets cover redaction and expected routing. Two focused regression checks cover sensitive-value replacement and preservation of non-sensitive wording.

These are bounded test cases, not proof of universal detection or production accuracy. Contextual detection depends on Presidio availability.
